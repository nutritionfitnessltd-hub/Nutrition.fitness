# Shiny Things through the existing Content Manager connector

The existing Sites MCP endpoint exposes `list_shiny_things`, `get_shiny_thing`, `create_shiny_thing` and `update_shiny_thing`. No new board or database is created. Sites authenticates the caller and supplies verified identity headers; the existing configured owner-email check gates every idea action. Shared Site viewers cannot access the administrator-only board through these tools.

The existing `NUFI_WORKER_TOKEN` is sent server-to-server to `content-worker-bridge`. The bridge retains its hash lookup and enabled/revoked connection check. Idea actions additionally require the existing `content-manager` connection and `worker:content-manager:` namespace. Other worker connections remain draft scoped. No public grants, RLS policies, credentials or audience changes are needed.

Records remain `nufi_studio_items` settings with `studio:idea:<UUID>` IDs. Tool `description` maps to `fields.summary`, `priority` to `fields.urgency`, `status` to `fields.state`, and `category` to `fields.category`. Existing records default to empty category and normal urgency. Saves use `nufi_studio_save` with the current revision and existing worker audit identity. Category is editable in the existing board modal and survives board edits.

List supports query/category/status/priority filters and pagination. Get returns the current revision. Create takes a generated UUID `requestId`, reused across retries, and maps it to the canonical board ID; an existing ID returns a conflict rather than duplicating the idea. Update patches only supplied fields and requires a positive saved revision. All successful saved responses include `id`, `url` and `revision`.

Writable statuses are `Saved` and `Parked`. Read results also represent `With Morgan`, `Ready to review`, `Converting` and `Project created`. The connector cannot fabricate a Morgan proposal, approve work, promote projects or edit converted ideas. Changing a title or description clears only the now-stale proposal/request metadata; priority/category changes preserve the proposal. Unknown internal fields and comments are retained.

Verification: board/bridge tests cover CRUD, field mapping, legacy defaults, partial patches, category preservation, IDs/URLs, paging, stale writes, invalid inputs, revoked connections, foreign namespaces and linked-project locks. The existing save RPC was tested in a rolled-back transaction. Connector scripts cover verified-owner isolation, strict schemas, MCP discovery/auth/origin handling, existing content tools and training routing. Builds pass. The existing six content approval/preview test failures reproduce on the unchanged base. After release, verify list/get using the connected plugin and compare the pre-existing board record checksum; do not leave a production test idea.

Example voice requests to a ChatGPT session where the connector is available: “Save a Shiny Thing called Referral challenge, category Growth, priority soon”; “List my urgent ideas”; “Park that idea for later.” Voice availability itself is controlled by the ChatGPT client; these are the same authenticated tools used by text conversations.
